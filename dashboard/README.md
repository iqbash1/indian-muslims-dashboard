# L4 Dashboard

`build.py` reads `canonical/*.csv` + `manifest/metrics.yaml` and writes the
pre-rendered static site to `docs/`. Cloudflare Workers (Static Assets)
auto-deploys `docs/` to https://muslimdata.in/ on every push to `main`.

## Build

```bash
.venv/bin/python dashboard/build.py
open docs/index.html
```

Idempotent. Re-run after any `canonical/` change.

## Build outputs

- `docs/index.html` — the home page (scorecard + card grid).
- `docs/about/index.html` — the About page (mission, pipeline, source list).
- `docs/js/analytics.js` — GA4 + Microsoft Clarity loader, IDs substituted
  from `GA4_ID` / `CLARITY_ID` constants at the top of `build.py`.
- `docs/m/{mid}/index.html` — per-metric OG stub pages (one per live
  metric). Each carries metric-specific Open Graph + Twitter Card meta so
  social previews render correctly when a permalink is shared; the body
  client-redirects into `/#{mid}` on the home page so the modal auto-opens
  for human visitors.
- `docs/canonical/*.csv` — copies of the L3 canonical CSVs (the card
  footer download links target these).

## Static assets (not regenerated by the build)

Favicons live in `docs/` and are committed directly, not emitted by
`build.py`: `favicon.svg` (the maroon mosque mark, hand-authored) plus
`favicon.ico` and `apple-touch-icon.png`, rasterised from the SVG with
`qlmanage -t` + Pillow. Regenerate the latter two only if the SVG changes.

## What it renders

A masthead (brand · About · GitHub · last-updated date), a value-prop H1,
a one-to-two-sentence headline finding, a muted preamble line (primary-
source count + how-to-read + an About link), a comparison-baseline toggle
(`vs all-India` ↔ `vs Hindu`), the responsive card grid (one card per
live metric, grouped into five themed sections), and below it a collapsed,
sortable + searchable scorecard table.

Cards adapt to the data via `render_metric_card()`:

- **Headline**: metric name, plain-English definition (italic line),
  Muslim value + unit + latest year, polarity tag ("↑ HIGHER IS BETTER"
  or "↓ LOWER IS BETTER"), a persistent ↗ open-affordance icon (top-right).
- **Chart**: card view shows only the Muslim line + a dashed comparison
  reference (source "All-India" when populated, else the per-year median
  across communities, labelled honestly). Hovering surfaces both values
  at the hovered year in one tooltip.
- **Comparison pills**: "vs all-India" (or "vs all religions (median)"
  when the median fallback is in play) plus a "Among communities" rank.
  Both render in HTML; the page toggle swaps which is visible.
- **Footer**: source name, hyperlinked to the metric's canonical CSV.
- **Details**: full state table or top-100 list, in a collapsible
  `<details>`.

## Modal view

Click any card → opens a modal that re-renders the chart at ~3× the
card's vertical real estate, with every community line visible (Hindu,
Christian, Sikh, Buddhist, Other) at lighter (medium-weight) labels.
The modal also surfaces an "About this measurement" panel with the full
definition + methodology notes from `manifest/metrics.yaml`. Prev/next
buttons (and ← / → keys) step through metrics in card order; the Share
button copies a permalink (`/m/{mid}/`); ESC / scrim click / × closes.

## Why static HTML

Provenance over interactivity. Every number is inlined into the page at
build time and traces L4 → L3 → L2 → L1 with SHA256 sidecar. No client-side
data fetch; no server runtime; the build is reproducible from the repo
state at any commit.
