# L4 Dashboard

Single static `docs/index.html`, built from `canonical/*.csv` by `build.py`. GitHub Pages serves it from `/docs`. Opens in any browser — no server, Chart.js from CDN.

Live: https://iqbash1.github.io/indian-muslims-dashboard/

## Build

```bash
python dashboard/build.py        # writes docs/index.html + copies canonical/*.csv into docs/canonical/
open docs/index.html
```

Idempotent; rebuild after any `canonical/` change.

## What it renders

A scorecard table (all metrics at a glance) followed by a responsive **card grid** — one card per live metric (those with a `display.scorecard` block in `metrics.yaml`), grouped by cluster. Cards are generated by `render_metric_card()` and adapt to the data:

- **Headline** — Muslim value + plain-language unit + latest year, with a "higher / lower is better" polarity pill.
- **Chart** — single-snapshot metric → a horizontal **community bar** (named religious communities, Muslim highlighted, All-India as a dashed baseline). Metric with ≥2 survey rounds → a **Muslim-vs-Hindu trend line** (dashed where `break_flag` marks a cross-round comparability caveat).
- **Comparison block** — "vs Hindu" gap + a "rank among communities" tier — the Muslim-vs-other-communities analog of hawaiidashboard.org's rank-of-50-states — or "vs All-India" where no rank applies.
- **Footer** — the source name, hyperlinked to the metric's canonical CSV.
- **Details** — full state table (snapshot) or latest-year community ranking (trend), in a `<details>`.

Status-bar counts (metrics / sources / canonical rows) are derived live from `canonical/` — no hardcoded numbers.

## Why static HTML

Provenance over interactivity. A single self-contained file any clone can open keeps the focus on data correctness; every number traces L4 → L3 → L2 → L1 with SHA256 sidecar provenance. "All-India" is always a baseline reference, never a peer community.
